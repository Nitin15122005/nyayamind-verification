## What belongs here

Fresh output produced by *running the pipeline (or a component of it) from this
workspace*. This directory never contains a copy of historical files from
`research/prototype/outputs/` — those stay in place and are referenced directly (e.g. by
`../evaluation/` and `../comparisons/`) rather than duplicated here. If you want to
display a historical result, link to its frozen path; only put a file here if it was
actually produced by running something *from this workspace*, after this step.

## Mandatory per-artifact metadata

Because production code, config, and model weights can all legitimately change over
time, any actual-output artifact placed here **must** be accompanied by a sibling
`<artifact_name>.meta.json` recording, at minimum:

```json
{
  "produced_at": "ISO-8601 timestamp",
  "repo_commit": "git rev-parse HEAD at run time",
  "config_snapshot": "sha256 of config/prototype.yaml used, or the full resolved config",
  "python_version": "...",
  "key_package_versions": {"torch": "...", "transformers": "..."},
  "device": "cpu | cuda:<name>",
  "seed": 42,
  "command": "the exact command line used to produce this artifact"
}
```

Without this, a future reader cannot tell whether an "actual output" reflects the current
production code or a stale run from before a fix — this was flagged explicitly during
this workspace's design review as a real risk (an undated actual-output artifact silently
going out of sync with pipeline code changes).

## Why this is separate from `expected_outputs/`

`expected_outputs/` is frozen, hash-verified, and never regenerated by a pipeline run.
`actual_outputs/` is exactly the opposite: it is expected to change every time the
pipeline, its config, or its dependencies change, and every artifact here should make
that change traceable via its `.meta.json` sibling.
